# ID Helper Bot 🆔

MAX-бот, который показывает идентификаторы: твой `user_id`, `chat_id`, ID
автора пересланного сообщения и ID человека, которым поделились как контактом.

## Что умеет

| Действие | Что показывает |
|----------|----------------|
| `/start`, `/help` | Приветствие и меню |
| `/myid` или кнопка «Мой ID» | `user_id`, имя, `@username`, ссылка `max://user/{id}` |
| `/chatid` или кнопка «ID чата» | `chat_id` и тип чата (диалог / группа / канал) |
| Переслать сообщение | `user_id` автора, `chat_id` источника, `mid` сообщения |
| Прислать контакт | `user_id` человека из контакта |
| Прислать фото, видео, файл | Тип вложения и идентификатор медиа |

К каждому ответу прикладывается кнопка «📋 Скопировать ID».

## Стек

- Python ≥ 3.12, пакетный менеджер **uv**
- Библиотека бота — `maxapi`, режимы polling и webhook
- Docker (multi-stage) + docker compose (local / prod)
- Makefile для рутинных команд

## Быстрый старт


## Режимы работы

Способ получения обновлений задаётся переменной `BOT_MODE`.

**`polling`** (по умолчанию) — ничего настраивать не нужно, бот сам опрашивает
MAX. Перед стартом снимает подписки на вебхук, иначе события не придут.

**`webhook`** — MAX сам присылает события на публичный HTTPS-адрес:

```bash
BOT_MODE=webhook
WEBHOOK_URL=https://bot.example.com/max/hook   # регистрируется в MAX
WEBHOOK_SECRET=your-secret                     # 5-256 символов: A-Z a-z 0-9 -
```

Путь локального сервера по умолчанию берётся из `WEBHOOK_URL`, так что
зарегистрированный адрес и обслуживаемый путь не разъезжаются. Переопределять
`WEBHOOK_PATH` нужно, только если реверс-прокси срезает префикс.

MAX требует HTTPS, поэтому в проде перед ботом ставится реверс-прокси: он
терминирует TLS и проксирует запросы на порт контейнера. `WEBHOOK_SECRET`
задавать стоит всегда — библиотека сама вернёт `403` на запрос без верного
заголовка `X-Max-Bot-Api-Secret`.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|------------|-------------|------------|
| `BOT_TOKEN` | да | Токен бота от @MasterBot |
| `BOT_MODE` | нет | `polling` (по умолчанию) или `webhook` |
| `LOG_LEVEL` | нет | Уровень логов, по умолчанию `INFO` |
| `ADMIN_IDS` | нет | ID админов через запятую (для служебных команд) |

Только при `BOT_MODE=webhook`:

| Переменная | Обязательна | Назначение |
|------------|-------------|------------|
| `WEBHOOK_URL` | да | Публичный HTTPS-адрес, регистрируемый в MAX |
| `WEBHOOK_SECRET` | нет | Секрет заголовка `X-Max-Bot-Api-Secret`, 5–256 символов |
| `WEBHOOK_HOST` | нет | Интерфейс локального сервера, по умолчанию `0.0.0.0` |
| `WEBHOOK_PORT` | нет | Порт локального сервера, по умолчанию `8080` |
| `WEBHOOK_PATH` | нет | Путь; по умолчанию берётся из `WEBHOOK_URL` |

Шаблон — в [`.env.example`](./.env.example). Сам `.env` в `.gitignore`.

## Структура

```
src/bot/
├── __main__.py        # точка входа: Dispatcher, запуск polling или webhook
├── config.py          # чтение и валидация окружения
├── formatters.py      # чистые функции форматирования (покрыты тестами)
├── handlers/
│   ├── ids.py         # команды и разбор входящих сообщений
│   └── callbacks.py   # нажатия inline-кнопок
└── keyboards/
    └── menus.py       # inline-клавиатуры
```

Роутеры подключаются в порядке `commands → callbacks → fallback`: catch-all
обработчик живёт в отдельном роутере и идёт последним, иначе он перехватил бы
команды.

## Заметки

- В групповых чатах боту нужны права администратора, иначе события не приходят.
- Публикация ботов в MAX (с августа 2025) доступна только юрлицам РФ;
  на локальную разработку это не влияет.
